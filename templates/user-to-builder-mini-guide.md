# User-to-Builder Mini-Guide

Last reviewed: 2026-07-24. See [sources and verification notes](../sources.md).

Use this when you are already using AI well for yourself and can see a small problem worth solving for other people.

## The Rule

Build the smallest useful version for a real workflow, with no sensitive data, no hidden decision-making, and a named human owner.

## 1. Pick the Problem

Finish:

- The repeated task is:
- The people affected are:
- The current workaround is:
- The cost of leaving it alone is:
- The reason I notice it is:

Good first builds:

- checklist
- prompt pattern
- intake form
- spreadsheet helper
- document template
- knowledge-base draft
- review workflow
- small internal tool

Avoid first builds that:

- make decisions about people
- process confidential or personal data
- send external messages automatically
- change records without review
- require deep integrations
- depend on perfect AI accuracy

## 2. Define the Boundary

- What can the tool do?
- What must it refuse or escalate?
- What data can it use?
- What data is prohibited?
- Who reviews the output?
- Who owns errors?

## 3. Prototype Safely

- Use public, synthetic, or redacted examples.
- Keep the workflow manual at first.
- Make outputs suggestions, not actions.
- Test common errors and edge cases.
- Ask one trusted peer to try it.

## 4. Decide Whether to Share

Before sharing beyond yourself:

- [ ] The problem is real for someone else.
- [ ] The data rules are clear.
- [ ] The output is reviewed by a human.
- [ ] The limits are visible.
- [ ] The owner is named.
- [ ] The workflow can be stopped.
- [ ] You know who to ask for approval if it touches work systems or data.

## 5. Scale Carefully

If people start relying on it, move it into the right governance process: tool approval, data review, security review, documentation, training, and support.
